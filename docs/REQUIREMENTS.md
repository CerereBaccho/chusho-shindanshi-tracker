# 要件定義書: 中小企業診断士 学習トラッカー

> **Document version**: 1.1
> **Last updated**: 2026-04-24
> **Target audience**: Claude Code / 開発者

---

## 1. 背景と目的

### 1.1 背景

中小企業診断士試験は合格に約1,000時間の学習が必要とされる難関資格で、働きながらの学習では時間管理が合否を分ける。市販の学習管理アプリは汎用的で、診断士試験特有の科目配分・2次試験との関連性・無料情報ソースとの統合が不十分。

### 1.2 目的

ユーザーの生活パターン(平日22:00-23:00の1時間)と2年計画(2026年4月〜2028年10月)に合わせ、日次タスクを自動生成し、無料情報ソースへの導線を一元化する。進捗を可視化して学習継続を支援する。

### 1.3 成功基準

- 1,000時間の学習到達までの進捗が日次で把握できる
- 毎日アプリを開くだけで「今日何をすべきか」が確定する
- 情報ソース探索の時間がゼロになる(リンク直達)

---

## 2. 利用者と利用シーン

### 2.1 主要利用者

インフラエンジニアとして本業を持ち、平日22:00-23:00の1時間を学習に充てる社会人受験者(おきやまさん1名を想定)。

### 2.2 典型的な利用シーン

平日夜22:00にアプリを開き、その日のフェーズとタスク3件を確認。リンクから教材(TBC YouTube、過去問ドットコム等)へ直接遷移し学習。23:00に学習時間を記録してタスクにチェックを入れる。週末は遡って記録補正や翌週の予習を行う。

## 3. 機能要件

| ID | 機能名 | 概要 |
|----|--------|------|
| F-1 | 学習開始日設定 | ユーザーが任意の日付を学習開始日として設定できる。設定値はブラウザストレージに永続化され、再訪時も保持される。 |
| F-2 | フェーズ自動判定 | 学習開始日からの経過日数に基づき、現在のフェーズ(例: 財務・会計①3級講義・企業経営理論期)を自動判定する。全14フェーズ(財務・会計4フェーズ+1次科目対策6フェーズ+総復習2フェーズ+2次対策1フェーズ+その他1フェーズ)をコード内定数として定義済み。 |
| F-3 | 日次タスク自動生成 | 現在のフェーズに応じ、その日に実施すべきタスク(2〜3件)を自動生成する。各タスクは「タイトル・詳細・所要時間目安・リソースURL」を持つ。合計所要時間は1日60分を基準とする。 |
| F-4 | タスク完了管理 | タスクごとにチェックボックスを表示し、完了状態を日付単位で記録する。チェック状態はブラウザストレージに日付キーで永続化される。 |
| F-5 | 学習時間記録 | 分単位で学習時間を入力・記録できる。同日複数回の記録は加算される。 |
| F-6 | 進捗サマリ表示 | 画面上部に3つのメトリクスを表示する。総学習時間(時間単位)、連続学習日数(直近から遡って時間または完了タスクがある日)、1,000時間目標までの残り時間。 |
| F-7 | 日付ナビゲーション | 前日・翌日・今日への移動ができる。過去日の記録補正や翌日の予習に対応する。 |
| F-8 | 無料情報ソース統合 | 各タスクから以下のリソースへ直接遷移できる。CPAラーニング、TBC早稲田出版YouTube、ほらっちチャンネル、石川秀樹先生の速習経済学、過去問ドットコム、過去問完全マスター、LEC公式過去問DL、AAS二次試験過去問DL。 |
| F-9 | データリセット | 確認ダイアログを経て全学習データ(開始日・日次状態)を削除できる。 |
| F-10 | 科目別進捗グラフ | 科目ごとの累計学習時間を棒グラフで可視化する。 |
| F-11 | 週次・月次サマリ | 週・月単位の学習時間合計、完了タスク件数、学習日数を表示する。 |
| F-12 | 土日用拡張タスク | 土日に追加確保できる日は、長時間用タスクセット(過去問演習2時間セット等)を別途提示する。 |
| F-13 | タスクの手動追加 | 自動生成タスク以外のアドホックな学習(セミナー参加、書籍読了等)を手動で追加・削除できる。 |
| F-14 | データエクスポート | 学習記録をCSVまたはJSONで出力できる。Zennへの学習記録ブログ投稿や、受験後の振り返りに利用する。 |
| F-15 | リマインダー通知 | 22:00時点でブラウザ通知を送り学習開始を促す。 |
| F-16 | 学習ロードマップ表示 | 全フェーズの一覧と各フェーズの状態(完了・進行中・未着手)、全体進捗パーセンテージを表示する。フェーズ定義はコード内定数として固定し、ユーザー側からの編集は行わない。 |

## 4. 非機能要件

### 4.1 パフォーマンス

画面初回表示は3秒以内。タスクチェック操作は100ms以内に反映される。

### 4.2 データ永続性

学習開始日・日次状態(タスク完了・学習時間)はブラウザのストレージに保存される。タブを閉じても再訪時にデータが復元される。

### 4.3 オフライン動作

一度ロードされれば、外部リソースへの遷移以外はオフラインで動作する。

### 4.4 アクセシビリティ

テキストサイズは11px以上。ダークモード・ライトモードの両方で視認性を確保する。

### 4.5 互換性

モダンブラウザ(Chrome / Safari / Firefox / Edge の最新版)で動作する。

## 5. データ設計

### 5.1 永続化キー

| キー | 形式 | 内容 |
|------|------|------|
| `start-date` | `YYYY-MM-DD` (string) | 学習開始日 |
| `day:YYYYMMDD` | JSON object | 日次状態。フィールド: `done` (array)、`minutes` (number) |

### 5.2 フェーズ定義(コード内定数)

各フェーズは以下のフィールドを持つ。

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `start` | number | 学習開始日からの経過日数(フェーズ開始) |
| `end` | number | 学習開始日からの経過日数(フェーズ終了) |
| `name` | string | フェーズ名 |
| `sub` | string | 期間説明 |
| `weeks` | number | 期間(週) |
| `tasks` | array | タスク配列 |

`tasks` の各要素は以下のフィールドを持つ。

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `title` | string | ✓ | タスク名 |
| `detail` | string | ✓ | 詳細説明 |
| `url` | string | - | リソースURL |
| `time` | number | ✓ | 所要時間(分) |

## 6. 前提と制約

### 6.1 前提

- 学習時間は平日22:00-23:00の1時間を基準とする
- 土日は同様の1時間を仮定し、追加確保は手動調整とする
- 試験日は2028年8月1次・2028年10月2次を目標とする(科目合格制度活用)

### 6.2 制約

- ブラウザストレージ依存のため、ブラウザデータを削除すると学習記録が失われる
- 複数デバイス間での同期は現バージョンでは非対応
- フェーズ定義はコード内定数として固定されており、ユーザー側からの編集は行わない(F-16参照)

---

## 7. リスクと対応

| リスク | 対応 |
|--------|------|
| データ消失 | F-14のエクスポート機能で定期バックアップを可能にする |
| 計画遅延 | F-11の週次サマリ・F-16のロードマップで進捗確認を促す |
| 学習継続 | F-15のリマインダー通知で開始時刻を固定化する |
